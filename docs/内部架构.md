# 内部架构

本文讲"为什么这样实现"，不是 API 文档。想改用法的看 [使用指南](使用指南.md)。

## 1. 两条进程，一条回环连接

```
┌──────────────────── DSH 进程 ────────────────────┐
│  index.js  apply(ctx, config)                     │
│    ├─ token.js    → 配对令牌                      │
│    ├─ server.js   → http/ws 监听 127.0.0.1:17333  │
│    │    ├─ GET /edge-bridge/ping   ← 扩展发现      │
│    │    └─ GET /edge-bridge  (Upgrade) ← 扩展拨号  │
│    ├─ bridge.js   → 连接池 / 鉴权 / 请求应答       │
│    ├─ controller.js → edge_bridge 工具 + 懒加载    │
│    ├─ tools.js    → 七个浏览器工具 + 文本渲染      │
│    ├─ capture.js  → 抓取引擎                       │
│    └─ kb.js       → 知识库写入 + kb.py             │
└───────────────────────────────────────────────────┘
                     ▲ ws://127.0.0.1:17333/edge-bridge
                     │
┌──────────────────── 浏览器 ──────────────────────┐
│  Edge MV3 扩展                                    │
│    ├─ background.js  service worker：拨号/重连/分发│
│    ├─ page.js        注入页面的三个函数            │
│    └─ popup           配对、诊断、抓取按钮         │
│         └─ chrome.scripting.executeScript / CDP    │
└───────────────────────────────────────────────────┘
```

**没有第三方依赖。** `ws.js` 是手写的 RFC6455 服务端（握手、分帧、掩码、ping/pong、关闭帧），约 346 行。这换来的是：装插件不用 `npm install`，DSH 升级不会因为依赖版本冲突而崩，离线可用。

代价是 WebSocket 的边缘情况要自己兜：分片消息、超大帧、半关闭。目前限制单帧 ≤ 4 MB（截图走 base64 会接近这个量级），超限直接关闭连接。

## 2. 端口与自动发现

```
插件：listen(17333) 失败 → 17334 → … → 17344
扩展：并行 GET http://127.0.0.1:<port>/edge-bridge/ping（12 个端口，700ms 超时）
      取第一个返回 {"ok":true,"name":"dsh-edge-bridge"} 的
      拼成 ws://127.0.0.1:<port>/edge-bridge 再拨号
```

为什么不用固定端口 + 配置：DSH 的 Web UI 端口每次启动都可能变，如果桥接端口跟着变，每次都要改扩展配置。现在**插件自己找空位、扩展自己找插件**，两端都不用配。

为什么不用广播/mDNS：Windows 上不可靠，且回环上的 12 次 HTTP 探测总共只要几毫秒。

## 3. 协议帧

JSON Lines over WebSocket，五种帧：

| 方向 | 帧 | 说明 |
| --- | --- | --- |
| ext → host | `{t:"hello", protocol, token, extension:{name,version}, browser:{name,version}, caps:[...]}` | 首帧，必须带令牌 |
| host → ext | `{t:"hello", ok:true, protocol, server:{name,version}, caps:[...]}` 或 `{ok:false, error}` | 鉴权结果 + 能力协商 |
| host → ext | `{t:"req", id, method, params}` | 请求 |
| ext → host | `{t:"res", id, ok, value \| error}` | 应答 |
| 双向 | `{t:"ping"}` / `{t:"pong"}` | 心跳，20 秒一次 |
| ext → host | `{t:"event", name, data}` | 单向事件（`tabs` 计数、`capture.page`、`capture.stop`） |

握手时序：

1. 扩展 `onopen` 立刻发 `hello`。
2. 插件核对令牌：不匹配 → 发 `{ok:false,error:"invalid pairing token"}` 并 `close(4003)`。
3. 匹配 → 记下 `extension` / `browser` / `protocol` / `caps`，回 `{ok:true, caps: HOST_CAPS}`，清掉 15 秒的鉴权定时器。
4. 之后任何未鉴权的非 hello 帧都会导致 `close(4003, "hello required before any other message")`。

关闭码约定：

| 码 | 含义 |
| --- | --- |
| `1000` | 正常关闭 |
| `1001` | 宿主关闭（DSH 退出） |
| `4001` | 心跳超时（120 秒无 pong） |
| `4003` | 令牌错误 / 未鉴权 |
| `4008` | 15 秒内没发 hello |

## 4. 能力位协商

这是 v0.3.0 从 BrowserSkill 借鉴的核心机制。

**问题**：插件与扩展是两个独立部署单元。升级插件后忘了重载扩展，会得到一个"看起来连上了、但某些方法永远失败"的状态。旧实现只能等第一次调用失败才发现，而且报错是 `this extension does not implement "page.inspect"`——模型看到这句时往往已经在任务中途。

**现在的做法**：

```
extension: caps: Object.keys(HANDLERS)        ← 声明本 build 真正能分发的方法
plugin:    HOST_CAPS = 11 个 method 名         ← 声明本 build 需要的方法
```

握手时双向比对：

- 扩展 `caps` 少于 `HOST_CAPS` → 插件打 warn，列出缺哪些；`edge_status` 的 `caps:` 行直接显示 `— missing page.act`。
- 调用前拦截：`request()` 检查目标方法在不在 `conn.caps` 里，不在就立刻 reject，附上扩展自报的能力清单和"去 edge://extensions 重新加载"的指示。
- 扩展 `caps` 为空（0.3.0 之前的构建）→ **放行**，靠扩展端报错兜底。这是刻意的降级：老扩展仍然能用，只是回到旧体验。

契约由 `tools/test-contract.mjs` 守护：`HOST_CAPS` 与 `HANDLERS` 的集合必须完全一致，不一致就红。新增一个 method 忘了同步另一侧时，它是唯一会立刻报警的地方。

## 5. 懒加载

```
会话开始:  [edge_bridge]                         ← 1 个工具，约 30 行描述
start 后:  [edge_bridge, edge_status, edge_tabs,
            edge_inspect, edge_read, edge_eval,
            edge_act, edge_screenshot]           ← 8 个，约 2000+ token
stop 后:   [edge_bridge]                         ← 回到 1 个
```

三个自动收起条件（空闲 30 分钟 / 断线 60 秒 / DSH 退出）配合 `edge_bridge` 的 `touch()`——`index.js` 包装了 `bridge.request`，任何一次浏览器调用都会重置空闲计时。

为什么不用"动态 tool schema"：DSH 的工具注册是显式的 `ctx.tools.register()`，`start` 就是把 7 个定义塞进去，`stop` 就是调用对应的 dispose 闭包。没有更聪明的办法，也不需要。

## 6. `ref` 的实现

`page.js` 注入到页面里执行，所以它能直接改 DOM：

```js
function refFor(element) {
  const existing = element.getAttribute('data-dsh-ref');
  if (existing) { usedRefs.add(existing); return existing; }
  const token = `e${++refSeq}`;
  try { element.setAttribute('data-dsh-ref', token); } catch { /* 某些 Shadow DOM 会拒绝 */ }
  usedRefs.add(token);
  return token;
}
```

三个细节：

- **先收集页面已有的 ref**（`usedRefs`），新 ref 从当前最大值继续，避免与上一次 inspect 的编号冲突。
- **同一个元素第二次 inspect 复用原 ref**，所以"inspect → 操作 → inspect → 操作"不会导致 ref 抖动。
- `setAttribute` 失败时静默——只影响这一个元素的 ref 稳定性，不影响其它。

定位顺序 `ref → selector → text` 写在 `resolveTarget()` 里。ref 用属性选择器查（`[data-dsh-ref="e12"]`），所以它和选择器一样快，但语义是"那个节点"而不是"那个位置"。

## 7. `effect_state` 的实现

动作执行前后各取一次快照：

```js
function snapshot(element) {
  return {
    value: element.value,
    checked: element.checked || element.getAttribute('aria-checked') === 'true',
    text: (element.innerText || '').slice(0, 120),
  };
}

function fingerprint() {
  const body = document.body;
  const elements = body ? body.getElementsByTagName('*').length : 0;
  const text = body ? (body.innerText || '') : '';
  const limit = Math.min(text.length, 20000);
  let hash = 5381;
  for (let i = 0; i < limit; i += 1) hash = ((hash * 33) ^ text.charCodeAt(i)) >>> 0;
  return `${document.title}|${location.href}|${elements}|${text.length}|${hash}`;
}
```

判定：

| 条件 | 结果 |
| --- | --- |
| 指纹变了 | `committed`，`the page changed immediately` |
| `value` 变了 | `committed`，`the field value changed` |
| `checked` 变了 | `committed`，`the checked state changed` |
| 元素文字变了 | `committed`，`the element text changed` |
| 都没变 | `unknown`，附"不要盲目重试"的建议 |

**为什么指纹要包含正文哈希**：v0.3.0 的第一版只算了 `标题|URL|元素数`。实测点击 `#btn` 后 `#readout` 从 `idle` 变成 `clicked!`，元素数不变、标题不变、URL 不变——于是每次都误报 `unknown`。加上 20000 字符的 djb2 哈希（约 0.5ms/次，可接受）之后，这类"改写已有节点"的效果才被抓到。

对应地，`test-page-in-edge.mjs` 里那条断言从"committed 或 unknown 都算过"收紧成"必须 committed"——宽断言会掩盖这类 bug。

## 8. 抓取管线

```
扩展 popup 点"启动抓取"
  → background.js 监听 tabs.onUpdated（status === 'complete'）
  → 发 {t:"event", name:"capture.page", data:{tabId, url, source}}
  → 插件 capture.js 收到事件
      → 通过 bridge 请求 page.read（maxChars 6,000,000）
      → 清洗：scope 回退、导航裁剪、阅读器拒收
      → kb.js 写三处（快照 / 条目.json / 清单.md）
      → 防抖 3 秒后跑 kb.py build + extract
  → 回写 popup 计数与图标徽标
```

**为什么写文件的是插件而不是扩展**：MV3 扩展没有任意文件系统权限，只有 `downloads` 或 File System Access（需要用户手势）。让扩展写知识库要么弹一堆保存对话框，要么走 `downloads` 目录再搬——都不如交给已经能直接写文件的宿主。

**为什么有"阅读器拒收"**：中文期刊的在线阅读器（知网、万方、超星）用 PDF.js 或 canvas 渲染，抓下来的 HTML 只有外壳。四条规则里任意命中就拒绝入库并在总结里记原因：

1. 正文几乎全是 `data:image` 内联图。
2. 有 canvas 且有效文字少于 1200 字。
3. ≥ 3 条 `- Page N` 或 ≥ 2 个阅读器工具条标记。
4. （隐含）`scope` 回退后仍然拿不到有效正文。

宁可不入库，也不写一条让日后检索出错、还要人工清理的垃圾条目。

## 9. 测试分层

| 套件 | 层 | 依赖 | 项数 |
| --- | --- | --- | --- |
| `test-bridge` | 传输 + 协议 | 无（真 WebSocket 假扩展） | 27 |
| `test-server` | 端口 + 发现 | 无 | 11 |
| `test-plugin` | `apply()` 全链路 | 无（临时 DSH_HOME + 假 KB） | 76 |
| `test-capture` | 抓取引擎 | 无 | 111 |
| `test-page-in-edge` | 注入函数 | 无头 Edge | 59 |
| `test-contract` | 跨文件契约 | 无（只读文件） | 34 |

设计原则：

- **假扩展优先**。前四套用一个真 WebSocket 客户端扮演扩展，按 method 返回固定值。这样能测协议、超时、断线、能力位，而不需要浏览器。
- **注入函数单独测**。`page.js` 的三个函数是通过 `Function.prototype.toString()` 序列化后注入的，所以测试直接用同样的方式拼字符串在真浏览器里 eval——测的就是生产代码路径。
- **契约测试兜底**。行为测试测不到"改了一处忘了另一处"，`test-contract` 只做文字级断言。

共 318 项断言，全绿是发布门槛。

## 10. 不做什么

以下都是 BrowserSkill 有、这里**刻意没有**的：

| 没做 | 原因 |
| --- | --- |
| Agent Window（独立受控窗口） | 目标就是操作你正在看的窗口；多一层窗口反而要来回切 |
| session / borrow 概念 | 有 DSH 会话就够了；再加一层会话管理只是状态 |
| ref-store 持久化 | ref 写在 DOM 上，页面没了它就没了——这正是期望的语义 |
| 网络抓包 / 请求重放 | 是调试工具，不是浏览能力；想看请求用 DevTools |
| 视频录制 | 与"省 token"背道而驰 |
| 操作审计 | 本地单用户场景，日志已经够了 |
| 远程服务器模式 | 回环是实现简洁性的前提；要远程请用 SSH 隧道 |
| 自更新 | 未上架商店，源码即分发；升级就是 `git pull` + 重新加载 |
| 多语言 UI | 插件面向一个用户，中文够了（locale 只做插件管理页的两条文案） |
