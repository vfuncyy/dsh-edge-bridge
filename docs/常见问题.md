# 常见问题

按"现象 → 原因 → 处理"组织。文中出现的字符串都可以直接在 `edge_status`、工具回执或 `E:/.dsh/logs/desktop-next.log` 里搜到。

---

## 连接类

### `the Edge extension is not connected. Ask the user to open the "DSH Edge Bridge" extension in Microsoft Edge and press Connect`

插件在监听，但没有任何扩展完成握手。依次查：

1. DSH 是否在运行、插件是否启用——`curl http://127.0.0.1:17333/edge-bridge/ping` 应返回 `{"ok":true,"name":"dsh-edge-bridge","protocol":1,...}`。
2. 扩展是否装着、是否被禁用（`edge://extensions` 里看开关）。
3. 扩展 popup 的状态：`未连接` / `重试中` / `令牌被拒`。

### `No Edge Bridge found on 127.0.0.1:17333-…Is DeepSeek Harness running with the plugin enabled?`

扩展扫完 12 个端口都没找到 `/ping`。三种可能：

- DSH 没起（最常见）。
- 插件装了但没启用，或 `apply()` 抛异常（看日志里 `edge-bridge:` 开头的行）。
- 端口被占到了 17344 之外——理论上不会，除非你改过 `port` 且超出探测区间。

### `the browser extension presented a wrong pairing token`

令牌不匹配。注意这里是**插件拒绝**，不是扩展连不上：TCP 与握手都通了。

- `edge_bridge(action="status")` 拿当前令牌，重新粘进 popup。
- 换过 profile 或删过 `<DSH_HOME>\edge-bridge-token` 时，旧令牌自然失效。
- 服务端用 `4003` 关闭，popup 会显示"令牌被拒"。

### `Last handshake error: …` 有值但 `Attached extensions: 0`

`lastError` 是**上一次**失败的原因，不代表现在。扩展重连成功后会清空；如果一直不空，说明它一直在重试失败。

## 版本与能力位

### `this extension does not implement "page.inspect" (protocol 1, build 0.2.0, caps: …)`

扩展是旧版，没实现该方法。回执里已经给出它自己声明的 `caps`。

处理：`edge://extensions` → 找到 `DSH Edge Bridge` → 点 **重新加载**。

### `edge bridge: the connected extension does not implement "page.inspect". It reports: … — reload the unpacked extension in edge://extensions …`

同样的原因，但**由插件提前拒绝**（v0.3.0 的能力位协商）。好处是不用等 15 秒超时。

### `edge_status` 显示 `caps:      (not reported — this extension build predates capability reporting, so calls are attempted blindly)`

service worker 还是 0.3.0 之前的构建。这是最迷惑的一种：**`manifest.json` 里的版本号已经是新的**（重启会重新读它），但 `background.js` 的代码还在内存里跑旧的。

> 记住这条：改了 `extension/` 下任何文件，必须到 `edge://extensions` 点 **重新加载**。只重启 DSH 或只重启 Edge 都不够。

### 日志里出现 `did not report its capabilities, so it is still running a build from before v0.3.0`

同上。这条 warn 就是专门为这个场景写的，看到它等于"扩展没重载"。

## 动作类

### `no element with ref e4 — refs are stamped by the last edge_inspect in this page; re-run edge_inspect and use its ref`

ref 失效。原因：页面导航过、局部重渲染过、或者上次 inspect 是很久以前。

处理：重新 `edge_inspect`，用新的 ref。**不要拿旧 ref 反复重试**——大概率永远不会成功。

### `expectation failed: expected text "Delete forever" but the target has "Press me" — nothing was done`

`expect` 拦住了动作，**一步都没执行**。这通常是好事：

- 如果"Press me"才是你要点的，说明选择器/ref 指错了元素——重新 inspect。
- 如果确实该是"Delete forever"，说明页面状态和你以为的不同——先 read/inspect 确认。

`effect_state: none` 是这个分支的标记。

### `effect_state: unknown`

动作已派发，但回执这一刻没观察到页面变化。

**不要重试。**先 `edge_read` 或 `edge_inspect` 看页面到底在哪一步。三种常见成因：

| 成因 | 特征 | 处理 |
| --- | --- | --- |
| 提交后跳转，回执早于导航 | 几秒后 URL 变了 | 用 `wait_for` / `wait_for_selector` 等目标态 |
| 网络请求未回 | 页面上有 loading 态 | `wait_for_text` 等结果文字 |
| 动作本来就没有可见反馈 | 页面完全没变 | 用 `edge_eval` 读内部状态确认 |

### `effect_state: committed` 但页面看起来没变

指纹包含正文前 20000 字符的哈希，所以"某个已有节点的文字改了"也算 committed——哪怕视觉上几乎看不出。这正是要的灵敏度：提交后的 toast、计数 +1、按钮变灰都会被抓到。

### `"page.act" timed out after 90000ms`

分两种：

- 回执后面还有 `effect_state: unknown` —— 动作发出去了，页面可能已经变了。**按 unknown 处理**。
- 报 `the page may still be loading` —— 目标元素一直没出现。检查 `wait_for` / `timeout_ms`。

### `NOT settled: #result-table never appeared`

动作本身成功了，但后续等待超时。别接着读空表——先确认动作是否真的生效。

### `no focused field to type into: pass a ref or a selector`

`edge_act(action="type")` 既不传 `ref` 也不传 `selector`，而页面当前没有聚焦的输入框。补一个 `ref`。

### `another debugger is attached to this tab (close DevTools for this tab, then retry)`

该标签页上已经挂着 DevTools。`edge_eval` 与整页截图需要独占 `chrome.debugger`。关掉 DevTools 再试。

## 读取类

### `edge_inspect` 输出 `No interactive elements matched.`

页面**真的**没有可点元素：可能内容全在 canvas 里、可能是 PDF 内置查看器、也可能整页是个图片。

区分另一句：`N interactive elements hidden by filter — …` 说明**有**匹配，只是被 `max_interactive` / `selector` / 可见性判断挡掉了。放开参数即可。

### `edge_inspect` 的 `iframe` 数量不为 0，但看不到里面的内容

跨域 iframe 读不到——content script 与 `Runtime.evaluate` 都只作用于主框架。

处理：把 iframe 的 URL 单独 `edge_tabs(action="open")` 开一个标签页，在那边 inspect。

### `edge_read` 返回的内容很短，`scope` 是 `auto:body(fallback)`

不是错误，是自动回退：候选容器（`main`/`article`/`#content`…）拿到的文字不足整页一半，于是改用 `<body>`。常见于把正文放在多个并列 `div` 里的站点。

如果正文还是缺失，说明它可能是懒加载的：先 `edge_act(action="scroll")` 再读，或者用 `wait_for_selector`。

### `edge_read` 的正文里出现 `(truncated)`

超过了 `max_chars`（默认 20000，上限 200000）。要么调大，要么用 `scope` 限定到单个区域。

### 表格读出来错位

`edge_read` 的 Markdown 表格对合并单元格、多级表头、跨行分组都会失真。要数据用 `edge_eval`：

```
edge_eval(code="$$('#table tbody tr').map(tr => [...tr.cells].map(td => text(td)))")
```

需要 `rowspan` / `colspan` 时，在 `edge_eval` 里直接读 `td.rowSpan` / `td.colSpan`。

## 页面与权限

### `Cannot access a chrome:// URL` / 受限页面

`edge://*`、`chrome://*`、扩展商店、`about:blank` 无法注入脚本。这是浏览器限制，不是插件缺陷。

### `file://` 页面报无法访问

到 `edge://extensions` → 该扩展的"详细信息" → 打开 **允许访问文件 URL**。

### 顶部出现"正在调试此浏览器"提示条

`edge_eval` 与整页截图走 CDP（MV3 禁止扩展内 eval），必然出现。调用结束会 detach，提示条消失。**不是故障，也不能关掉**。

### `tab N no longer exists; call edge_tabs action=list to pick a live tab`

标签页被关了。重新 `edge_tabs(action="list")` 拿新的 id。

## 抓取类

### 抓取按钮点了没反应

抓取由**宿主插件**执行（只有它有文件系统权限）。检查：

1. DSH 在运行、插件已启用、扩展已连接。
2. 扩展 popup 有没有显示错误。
3. 日志里 `edge-bridge:` 开头的行。

### 抓到了但知识库没变化

看 `<kbRoot>/补充/条目.json` 的 mtime。若没变：

- `kbRoot` 配错（默认取 `DSH_KB_ROOT`，否则 `$DSH_HOME/knowledge-base`；不存在的路径会失败）。
- `kb.py` 不在 `kbRoot` 下，或 `kbPython` 指向不存在的解释器。
- 会话总结里会记下失败原因与前几行 stderr。

### 页面被"拒绝入库"

见使用指南第 10 节的四条拒收规则。最常见的两种：

- **`data:image` 占主体**（图片型扫描件）。
- **阅读器外壳**：正文里有 `- Page N` 或阅读工具条标记，且有效文字太少。

这是设计选择：**宁可不入库，也不写垃圾条目**。正确做法是下载 PDF 走文献入库流程。

### 删错了条目

```
node edge-bridge/tools/remove-capture.mjs sup123
```

同时删条目、快照、全文、卡片并重建索引；删除前自动备份 `条目.json.bak-<时间戳>`。

## 环境与工具链

### 本机没有 `node`

DSH 桌面端自带 Electron 运行时。跑测试用：

```
export ELECTRON_RUN_AS_NODE=1
"D:/DeepSeek Harness/DSH NEXT/DSH NEXT.exe" edge-bridge/tools/test-bridge.mjs
```

### 改了插件代码不生效

模块缓存不会自动刷新。用 `plugin_manager` 把 bundle 关掉再开：

```
plugin_manager(action="set_bundle", target="dsh-edge-bridge", enabled=false)
plugin_manager(action="set_bundle", target="dsh-edge-bridge", enabled=true)
```

### 改了扩展代码不生效

`edge://extensions` → **重新加载**。见上文"版本与能力位"。

### `test-page-in-edge.mjs` 打印 `SKIP`

说明这台机器上无头 Edge 起不来（或没装在标准路径）。测试退出码 0，不算失败。手动验证时用 `file:///.../tools/fixture/page-fixture.html`——**不要**起本地 http server 喂浏览器，某些沙箱环境会拦回环出站，导致 `Frame is showing error page`。

## 还是不通？

收集这四样，问题基本能定位：

1. `edge_bridge(action="status")` 的完整输出。
2. `curl http://127.0.0.1:17333/edge-bridge/ping` 的结果。
3. 扩展 popup 的状态与最近一次错误。
4. `E:/.dsh/logs/desktop-next.log` 里 `edge-bridge:` 开头的最近 20 行。
