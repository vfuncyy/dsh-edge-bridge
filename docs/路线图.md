# 路线图

原则：**只加能减少失败的能力，不加能增加能力数量的能力。** 这个插件的价值在于"零依赖、一个进程、省 token"，任何扩大部署面的功能都默认不做。

## 下一个版本（0.4.0）

按优先级：

### 1. 批量动作的失败聚合

现在批量点击要模型逐个调用 `edge_act`，中途失败即中断。计划加 `edge_act` 的 `steps` 数组形式：按顺序执行，遇到 `expect` 失败或 `effect_state: unknown` 就停在原地并返回已完成/未执行清单。目标是把"点掉一百个确认"从一百次往返变成一到两次。

### 2. `edge_inspect` 的稳定顺序

同页面内容不变时，`ref` 编号应稳定（当前已做复用），但 `Interactive` 的排列严格按 `y` 坐标，同 `y` 的元素顺序取决于 DOM 顺序。计划改为 `y` 后按 `x`、再按 DOM 序，避免两列布局下顺序抖动。

### 3. 抓取前的结构性判重

同一 URL 重复抓取现在会产生多条 `sup` 条目。计划在 `kb.js` 里按 `url + 正文前 N 字哈希` 判重，命中则更新快照与 `capturedAt` 而不新增条目。

## 再看（0.5.0 或更晚）

- **`edge_read` 的分块读取**：超长页面现在只能截断。计划加 `chunk` 参数，按正文块返回并支持 `chunk_index` 续读，替代调大 `max_chars`。
- **Shadow DOM 与复杂组件的 `ref` 稳定性**：`setAttribute` 在部分 Shadow Root 里被拒绝，目前静默跳过。计划用 WeakMap 兜一层（只在本页面生命周期内有效）。
- **`edge_eval` 的返回值体积控制**：现在只按 100000 字符截断。计划加 `max_chars` 参数并在截断时给出建议（比如"用 `.slice(0, 50)`"）。
- **无头模式下的测试覆盖扩展**：`test-page-in-edge` 只测 `page.js` 的三个函数，`background.js` 的方法分发目前由假扩展覆盖。计划用一个真扩展在无头 Edge 里跑（需要 `--load-extension`，目前认为价值不足以抵消复杂度）。

## 明确不做

| 项 | 原因 |
| --- | --- |
| 云端浏览器 / 远程托管 | 回环是实现简洁性的前提，交账号是这套方案要避免的事 |
| Agent Window / 独立受控窗口 | 目标就是操作你正在看的窗口 |
| 操作审计与录像 | 本地单用户；录像与"省 token"直接冲突 |
| 网络抓包 / 请求重放 | 那是 DevTools 的活 |
| 上架 Edge 商店 | 会引入签名、审核与自动更新链路；源码即分发更符合这个项目的体量 |
| 自更新 | 同上 |
| 多语言 UI | 一个用户，中文够了 |
| 与其它浏览器（Chrome/Firefox）同时支持 | 代码里没有 Edge 专属逻辑，理论上可直接加载到 Chrome；但只在 Edge 上验证过，不承诺 |

## 想提需求

开 issue 时请写清三件事：**你想做什么、现在卡在哪一步、回执里最关键的那几行**。如果能让 `test-contract` 或某一套行为测试复现，就更好了——这个项目判断一个需求值不值得做，标准是"它是否让某类失败变得可判断"。
