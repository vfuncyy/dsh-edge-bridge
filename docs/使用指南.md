# 使用指南

本文是 `dsh-edge-bridge` 的完整用法。安装步骤见 [README](../README.md)；这里假设插件已装、扩展已连、`edge_status` 显示 `caps: 11 method(s)`。

---

## 0. 心智模型

理解三件事就够了：

1. **工具是懒加载的。** 会话开始时只有一个 `edge_bridge` 控制工具。它不占什么上下文，因为浏览器能力大多数时候用不上。要用就 `start`，七个浏览器工具从**下一步**起出现在工具列表里。
2. **你说的是"标签页"，不是"网页"。** 每个工具都接受 `tab_id`；省略时用最后聚焦窗口的活动标签。`edge_tabs(action="list")` 是唯一可靠的入口，不要凭记忆猜 id。
3. **先看，再动。** `edge_inspect` 给你结构，`edge_read` 给你正文，`edge_act` 才动手。跳过前两步直接写选择器，是最常见的失败原因。

```
edge_bridge(start)
  └─ edge_tabs(list)            ← 我在哪
       └─ edge_read / edge_inspect   ← 页面上有什么
            └─ edge_act(ref=...)/ edge_eval   ← 做一件事
                 └─ 读回执的 effect_state     ← 成了没有
```

## 1. 控制工具：`edge_bridge`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `action` | `start` \| `stop` \| `status` | 必填 |

- `start`：注册七个浏览器工具。**下一次模型调用**才能看到它们——同一条消息里调完 `start` 立刻调 `edge_tabs` 会报"未知工具"。
- `stop`：立刻卸载七个工具，从上下文中移除。WebSocket 连接**不断**，扩展仍然连着，`edge_status` 之类的 reconnect 信息仍然可查。
- `status`：返回端点、连接数、每条连接的扩展版本与能力位、配对令牌、抓取状态。

回执样例：

```
Edge browser tools are ON — edge_tabs, edge_inspect, edge_read, edge_eval, edge_act and edge_screenshot become available from the next model step.
```

三个自动收起条件，避免忘掉 `stop` 而一直背着上下文：

| 条件 | 默认 | 配置键 |
| --- | --- | --- |
| 空闲超时 | 30 分钟无调用 | `idleTimeoutMinutes` |
| 扩展断线 | 断线 60 秒后 | `stopWhenDisconnected` |
| DSH 退出 | 立即 | — |

## 2. 连接状态：`edge_status`

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `include_tabs` | boolean | false | 同时列出所有标签页 |

回执样例（已连接）：

```
Bridge endpoint: ws://127.0.0.1:17333/edge-bridge
Attached extensions: 1

Connection edge-1
  extension: DSH Edge Bridge 0.3.0
  browser:   Microsoft Edge 157.0.0.0
  remote:    127.0.0.1:51822
  since:     2026-11-08T18:58:56.867Z
  caps:      11 method(s)

Pairing
  token: YOUR-PAIRING-TOKEN
  token file: <DSH_HOME>\edge-bridge-token
```

`caps:` 行是本版本新增的诊断核心：

| 显示 | 含义 | 处理 |
| --- | --- | --- |
| `caps:      11 method(s)` | 扩展声明了全部 11 个方法 | 正常 |
| `caps:      11 method(s) — missing page.act` | 扩展较旧 | 到 `edge://extensions` 点**重新加载** |
| `caps:      (not reported — …)` | service worker 还是 0.3.0 之前的构建 | 同上 |

未连接时会是：

```
Bridge endpoint: ws://127.0.0.1:17333/edge-bridge
Attached extensions: 0
Status: NOT CONNECTED — the DSH plugin is listening, but no Edge extension has completed the handshake.
Last handshake error: the browser extension presented a wrong pairing token
```

`Last handshake error` 只有两种：令牌错，或从来没来过。前者去 popup 重新粘令牌，后者点扩展看它是不是在重试。

## 3. 标签页：`edge_tabs`

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `action` | `list`\|`open`\|`navigate`\|`activate`\|`close`\|`reload` | `list` | |
| `tab_id` | integer | 活动标签 | `navigate`/`activate`/`close`/`reload` 必填 |
| `url` | string | — | `open`/`navigate` 必填；省略协议时补 `https://` |
| `filter` | string | — | 在标题与 URL 上做子串匹配（不区分大小写） |
| `limit` | integer | 50（上限 200） | |
| `active` | boolean | true | `open` 后是否切到前台 |
| `wait_for_load` | boolean | true | 等到 `status === 'complete'`（上限 30 秒） |
| `wait_for_selector` | string | — | 等某个元素出现（上限 20 秒），用于 SPA 首屏 |

回执样例：

```
Microsoft Edge — 3 tab(s) in 2 window(s)

Window 1288291366 (focused)
  tab 42 [active] — Fixture Page
      file:///C:/work/edge-bridge/tools/fixture/page-fixture.html
  tab 2039573698 [pinned, loading] — GitHub · Where software is built
      https://github.com/

Window 1288291370
  tab 2040000123 — 知网检索结果
      https://kns.cnki.net/kns8s/defaultresult/index
```

这些短语是可操作的：

- 没有窗口时你会看到 `Microsoft Edge is connected but has no window open. Call edge_tabs action="open" — it creates a window when none exists.`
- `filter` 没匹配上时是 `Microsoft Edge is connected, but no tab matched. Drop "filter" to see every tab.`——不要以为是断线。
- 状态标记 `[active, pinned, discarded, loading]` 里，`discarded` 的标签页会被重新加载一次；`loading` 说明还没就绪，加 `wait_for_load`。

## 4. 读正文：`edge_read`

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `tab_id` | integer | 活动标签 | |
| `format` | `markdown`\|`text`\|`html` | `markdown` | |
| `scope` | `auto`\|`body`\|`main`\|CSS 选择器 | `auto` | 正文范围 |
| `max_chars` | integer | 20000（上限 200000） | 超长截断并标记 `(truncated)` |
| `include_links` | boolean | false | 附全部链接 |
| `drop_tags` | string | `script,style,noscript,template,svg,canvas,iframe,nav,footer,aside` | 剔除的标签 |
| `wait_for_selector` | string | — | 等元素出现再读（上限 10 秒，超时只记日志不算失败） |

回执样例：

```
Microsoft Edge tab 42 — "Fixture Page"
URL: file:///C:/.../page-fixture.html
markdown · 1284 chars

# Fixture Title

## Section one
**bold** and *italic* and a [relative link](file:///.../relative/link) ...

Outline:
  - Fixture Title
    - Section one
      - Subsection

---

<正文>

Links (2):
  - relative link — file:///.../relative/link
  - absolute — https://example.com/absolute
```

`scope=auto` 的行为值得记住：先依次探测 `main, article, [role=main], #content, #main, .content, .post, .article`，取第一个 `innerText` 超过 200 字的。**如果这个容器拿到的文字不到整页的一半**，自动回退到 `<body>`，并在回执里把 `scope` 标成 `auto:body(fallback)`。所以看到 `auto:main` 不一定是好的——`auto:body(fallback)` 才是"候选容器没兜住"的信号。

`format=html` 会返回清洗过的 HTML（同样剥掉 `drop_tags`），适合需要保留结构但不需要 Markdown 的场合。

**不要用 `edge_read` 取结构化数据。** 表格会被渲染成 Markdown 表格，但合并单元格、多级表头、跨行分组都会失真。要数据用 `edge_eval`。

## 5. 看结构：`edge_inspect`

这是最重要的一个工具，也是最容易被跳过的一个。

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `tab_id` | integer | 活动标签 | |
| `selector` | string | — | 只转储这个子树 |
| `max_interactive` | integer | 80（上限 400） | 最多列多少个可点元素 |
| `max_lists` | integer | 12（上限 40） | 最多列多少个表格/重复列表 |
| `wait_for_selector` | string | — | 等元素出现（上限 20 秒） |

回执样例：

```
Fixture Page
file:///C:/.../page-fixture.html
complete · 5/6 interactive · 1 list(s) · height 1284

Outline:
  - Fixture Title
    - Section one
      - Subsection

Lists:
  table #results — 3 row(s) × 2
    | Title | Year |
    | ---- | ---- |

Interactive:
  e1 html > body > nav > a role=a — Navigation should be stripped
  e2 html > body > header > h1 — Fixture Title
  e4 #btn role=button type=button — Press me
  e5 #field role=input type=text
  e6 #about-more role=button type=button — Read more about it
  … 1 more — raise max_interactive, or pass selector to focus on one region.

Pass a ref (the token before the selector) to edge_act rather than a selector when the page may re-render.
```

五个可读信号：

1. **第三行的 `5/6 interactive`** —— 分母是页面上匹配到的可交互元素总数，分子是列出来的。差值是 `hiddenInteractive`。
2. **`ref` 在最前**（`e4 #btn`）。这就是接下来要交给 `edge_act` 的东西。
3. **`role=` / `type=`** —— 用来区分同名按钮（一个 `type=submit`，一个 `type=button`）。
4. **`Lists:` 的行数与样例行** —— 先估数据规模，再决定用 `edge_eval` 抽全量还是只取前 N 行。
5. **`height` 与 `iframe`** —— 高度很大意味着有懒加载；`iframe` 非零意味着关键内容可能在别的域里。

被过滤为空时：

```
42 interactive elements hidden by filter — disabled, invisible, or longer than a control label. Raise max_interactive, drop the filter, or open the cross-origin iframe in its own tab and inspect there.
```

这跟 `No interactive elements matched.` 是两件事：后者是真的没有可点元素（可能内容在 canvas 里），前者是被参数挡掉了。

## 6. 稳定 `ref`：为什么不要用选择器

`edge_inspect` 会给每个被列出的可见元素写上 `data-dsh-ref="e12"`。这个属性是**插件在页面上真实写进去的**（可以在 DevTools 里看到），因此：

- 页面局部重渲染时，React/Vue 可能把 `#btn` 换成另一个节点，选择器指到别的地方；`data-dsh-ref` 跟着 DOM 节点走，或者跟着一起被销毁——两种情况都是**你想要的**。
- 同一个页面上重复 inspect 会**复用**已有 ref，不会每次生成新的。

失效时的报错是明确的：

```
no element with ref e4 — refs are stamped by the last edge_inspect in this page; re-run edge_inspect and use its ref
```

看到这句就说明页面换过了。**重新 inspect**，不要拿旧 ref 硬试。

选择器仍然可用，适合两类场合：跨会话的固定页面（`#search-input` 三年没变过），以及在 `edge_eval` 里手写 `querySelector`。

## 7. 动手：`edge_act`

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `action` | `click`\|`type`\|`hover`\|`scroll`\|`wait`\|`select`\|`press` | 必填 | |
| `ref` | string | — | 来自 `edge_inspect`，如 `e12`；**优先级最高** |
| `selector` | string | — | CSS 选择器；无 `ref` 时使用 |
| `text` | string | — | 目标文字；既无 ref 也无 selector 时按文字找（取文字最短的匹配） |
| `expect` | object | — | 动作前断言，见下 |
| `amount` | integer | — | `scroll` 的像素数；省略 = 滚到底 |
| `submit` | boolean | false | `type` 后按回车并提交表单；`press` 配合回车时同理 |
| `timeout_ms` | integer | 10000 | 等待目标出现的上限 |
| `wait_for` | string | — | 动作后再等某个选择器出现 |
| `wait_for_text` | string | — | 动作后再等某段文字出现 |
| `wait_timeout_ms` | integer | 15000（上限 120000） | 上面两个等待的上限 |

### 7.1 基本动作

```
edge_act(action="click", ref="e4")
→ Microsoft Edge tab 42 — clicked ref e4
  effect_state: committed — the page changed immediately

edge_act(action="type", ref="e5", text="hello world")
→ Microsoft Edge tab 42 — typed "hello world" into ref e5
  effect_state: committed — the field value changed

edge_act(action="select", selector="#city", text="杭州")
→ … selected "杭州" in #city
  effect_state: committed

edge_act(action="press", selector="#q", text="Enter", submit=true)
edge_act(action="scroll", amount=1200)
→ … scrolled 1200px; y=1200 of 8400
edge_act(action="hover", ref="e7")
```

`type` 不传 `ref`/`selector` 时写入**当前聚焦的输入框**；没有聚焦时会明确报错 `no focused field to type into: pass a ref or a selector`，不会往 `body` 上乱打字。

### 7.2 `expect`：在动手前拦一下

```json
{
  "action": "click",
  "ref": "e12",
  "expect": { "text": "删除" }
}
```

四类断言，全部通过才执行：

| 键 | 比较对象 | 语义 |
| --- | --- | --- |
| `text` | `innerText` | **精确相等**（会先归一化空白） |
| `value` | `value` 属性 | 精确相等 |
| `checked` | `checked` | 布尔相等 |
| `attribute` | `{ name, value }` | 该属性精确相等；回执里写作 `@name` |

不匹配时：

```
Error: expectation failed: expected text "Delete forever" but the target has "Press me" — nothing was done

effect_state: none — the expectation failed before the click
```

两个要点：

- **"nothing was done" 是字面意思**：目标元素没有被点击、没有被聚焦、没有派发任何事件。可以安全地重新 inspect 后再试。
- **`expect` 只作用于这一次调用。** 它不会记忆，也不会因为上次通过就跳过。

典型用法是把"我就是想点那个写着 X 的按钮"写成断言，让失败发生在没有副作用的一侧。

### 7.3 `effect_state`：三值回执

每次 `edge_act` 的末尾都有一行：

| 值 | 含义 | 你该做什么 |
| --- | --- | --- |
| `committed` | 回执时页面确实变了（指纹变化 / 输入值变化 / 勾选状态变化 / 元素文字变化） | 继续下一步 |
| `unknown` | 动作已派发，但**回执这一刻**没有观察到变化 | **不要重试**。先 `edge_read` 或 `edge_inspect` 看页面状态，再决定 |
| `none` | 被 `expect` 拦住，一步都没执行 | 修正断言或目标后重试 |

`unknown` 最常见的三种成因：提交后跳转需要时间；触发了网络请求但回包慢；动作是幂等的但界面上没有任何可见反馈（比如上报埋点）。**这三种都不该重试**——重试可能提交两次。

超时也会明确告诉你 `unknown`：

```
edge_act: "page.act" timed out after 90000ms (the page may still be loading, or the extension stopped responding)

effect_state: unknown — the action was sent and may have committed. Do NOT repeat it blindly; call edge_inspect or edge_read first to see where the page stands.
```

指纹是怎么算的：`标题 | URL | 元素数 | 正文长度 | 正文前 20000 字符的哈希`。所以"点了一下，只是改了一段已有节点的文字"（最常见的情况）也能被抓到——v0.3.0 修的就是这个 bug。

### 7.4 稳定化等待

动作引发异步更新时，用末尾的等待参数，比让模型自己 sleep 好：

```
edge_act(action="click", ref="e12", wait_for="#result-table", wait_timeout_ms=30000)
→ … clicked ref e12
  settled: #result-table
  effect_state: committed
```

没等到不会失败，只是把回执写成 `NOT settled: #result-table never appeared`——**这句要当真**：动作可能没生效，或者慢于预期，别接着往下读空表。

## 8. 取数据：`edge_eval`

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `code` | string | 必填 | 在页面上下文里执行的 JS |
| `await_promise` | boolean | true | 自动 await 返回的 Promise |
| `timeout_ms` | integer | 20000（上限 120000） | |
| `wait_for_selector` | string | — | 先等元素 |
| `wait_for_text` | string | — | 先等文字 |

内置七个助手，省掉每次都写样板：

| 助手 | 作用 |
| --- | --- |
| `$(sel)` / `$$(sel)` | `querySelector` / `querySelectorAll`（转成数组） |
| `text(el)` | 归一化后的 `innerText` |
| `sleep(ms)` | 等待 |
| `waitFor(sel, ms)` | 轮询等元素，超时抛错 |
| `waitText(str, ms)` | 轮询等文字 |
| `clickText(label)` | 按文字找最短匹配的控件并点击（带 scrollIntoView） |

典型用法：

```
edge_eval(code="$$('#results tbody tr').map(tr => [...tr.cells].map(td => text(td)))")
```

```
edge_eval(code="({ title: document.title, rows: $$('table').length, canvas: $$('canvas').length })")
```

```
edge_eval(code="await waitFor('#data-ready', 15000); return $$('.row').length")
```

三种写法都能跑：表达式（`document.title`）、函数体（含 `return`）、以 `await` 开头的异步体。返回 `undefined` 或不可序列化的值时会归一化成字符串类型，不会静默丢失。

**注意两点**：`edge_eval` 走 `chrome.debugger`，Edge 顶部会出现"正在调试此浏览器"；返回内容超过 100000 字符会截断并标 `(truncated)`。

## 9. 截图：`edge_screenshot`

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `tab_id` | integer | 活动标签 | |
| `full_page` | boolean | false | 整页（滚动拼接，上限 20000px 高、4096px 宽） |

| `quality` | integer | 80 | 仅 jpeg |
| `path` | string | `edge-artifacts/edge-<tab>-<时间戳>.<ext>` | 相对工作区解析，绝对路径原样使用 |

## 10. 抓取进知识库

这部分不在 `edge_*` 工具里，而是扩展 popup 的三个按钮：

| 按钮 | 行为 |
| --- | --- |
| **启动抓取页面** | 开始监听；之后每次页面加载完成（`tabs.onUpdated` 到 `complete`）就把当前页抓进知识库 |
| **停止抓取页面** | 停止监听，并在工作区写一份会话总结（存了哪些页、失败几个、失败原因） |
| **批量抓取已打开的页面** | 一次性把当前所有可抓的标签页写进去 |

**只有宿主插件有文件系统权限**，扩展只发指令。所以这需要 DSH 正在运行、插件已启用、配对已完成。

每次抓取写三处（`<KB>` 是解析后的知识库根目录）：

| 位置 | 内容 |
| --- | --- |
| `<KB>/补充/原文/<collection>/<日期>_<时刻>-<标题>.html` | 自包含快照（内联样式，离线可读） |
| `<KB>/补充/条目.json` | 追加一条 `supNNN`：`type=webpage`、`container=域名`、`abstract=正文前 220 字`、`tags` 带域名 |
| `<KB>/<collection>/清单.md` | 人类可读的清单，一行一条 |

随后自动调用 `kb.py build` 与 `kb.py extract`，于是可以直接检索：

```
kb.py search 关键词 --collection 页面抓取
```

会话总结落在 `edge页面抓取/`：

```
edge页面抓取/
├─ 总结/2026-11-09_0312-会话总结.md
├─ index.json
├─ index.md
└─ README.md
```

**抓取质量的四条保证**：

1. 正文上限 600 万字（`MAX_PAGE_CHARS`），不截断；真截断会在快照里标注。
2. `scope=auto` 拿到的正文不足整页一半时回退 `<body>`。
3. 站点导航只在"首个标题之前、且是 ≥5 个链接、且没有句末标点"时裁掉，不会误伤正文里的链接列表。
4. **阅读器外壳拒收**：正文几乎全是 `data:image`、或者有 canvas 且有效文字少于 1200 字、或者出现 ≥3 条 `- Page N` / ≥2 个阅读器工具条标记——**宁可不入库，也不写一条垃圾条目**。PDF.js、期刊阅读器、图片型扫描页都属于这一类，正确做法是下载 PDF 再走文献入库流程，而不是抓 HTML。

抓错了想撤销：

```
node edge-bridge/tools/remove-capture.mjs sup123
```

它会同时删掉条目、快照、全文和卡片，并重建索引；删除前自动备份 `条目.json.bak-<时间戳>`。

## 11. 配置项

九个键，写在 `cordis.patch.yml` 或 profile 的插件配置里：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `port` | `17333` | 监听端口；被占用时在 17344 以内顺延 |
| `token` | 自动生成 | 配对令牌；默认落 `<DSH_HOME>\edge-bridge-token` |
| `autoStart` | `false` | 加载即注册七个浏览器工具（等于每次会话都付上下文成本） |
| `idleTimeoutMinutes` | `30` | 空闲多久自动 stop；`0` = 不超时 |
| `stopWhenDisconnected` | `true` | 扩展断线 60 秒后自动 stop |
| `captureTitle` | `edge页面抓取` | 会话总结工作区名 |
| `captureDir` | 自动 | 抓取产物目录，默认在工作区下 |
| `kbRoot` | `$DSH_HOME/knowledge-base` | 知识库根目录（或用 `DSH_KB_ROOT`） |
| `kbCollection` | `页面抓取` | 知识库 collection 名 |
| `kbPython` | DSH 内置 python | 跑 `kb.py` 的解释器 |

完整说明见 [配置参考](配置参考.md)。

## 12. 一条完整的工作流

目标：从某个后台列表里，把第二页的十条记录导出。

```
1. edge_bridge(action="start")
2. edge_tabs(action="list", filter="后台")
3. edge_inspect(tab_id=123)
      → 看到 e8 是"下一页"，e10..e19 是十条记录，Lists 显示 10 row(s)
4. edge_act(action="click", ref="e8", expect={text:"下一页"}, wait_for="#list-body")
      → effect_state: committed
5. edge_inspect(tab_id=123, selector="#list-body")
      → 确认还是十条，ref 变了
6. edge_eval(code="$$('#list-body tr').map(tr => [...tr.cells].map(td => text(td)))")
      → 拿到二维数组
7. edge_bridge(action="stop")
```

第 4 步的 `expect={text:"下一页"}` 不是多余的：如果第 3 步和第 4 步之间页面自己刷新了，`e8` 可能已经被复用成"清空数据"。断言让这种事故变成一次无害的失败。

## 13. 边界

| 情况 | 行为 |
| --- | --- |
| 跨域 iframe | content script 与 `Runtime.evaluate` 都只作用于主框架。`edge_inspect` 报 `iframeCount`；把 iframe 的 URL 单独开标签页 |
| `file://` | 需要在 `edge://extensions` 里勾选"允许访问文件 URL" |
| `edge://*`、`chrome://*`、扩展商店、PDF 内置查看器、`about:blank` | 明确报错，不会静默失败 |
| 需要 `chrome.debugger` 的操作 | `edge_eval`、整页截图会触发"正在调试此浏览器"提示条 |
| 页面在用户手里被切走 | 不跟随；`tab_id` 是稳定的，切走不影响已发起的调用 |
| 多个 Edge 窗口 | 全部可见，`edge_tabs` 按窗口分组；`tab_id` 全局唯一 |
| 多个扩展同时连 | 连接池保留多条，但默认用**最后握手**的那条；多浏览器场景请显式检查 `edge_status` |
