# 配置参考

插件的配置写在 bundle 的 `cordis.patch.yml` 里，或通过 profile 的插件配置覆盖。全部九个键（另加三个可选路径键）如下。

## 全表

| 键 | 类型 | 默认 | 作用 |
| --- | --- | --- | --- |
| `port` | integer | `17333` | 监听端口 |
| `token` | string | 自动生成 | 配对令牌 |
| `autoStart` | boolean | `false` | 加载即注册浏览器工具 |
| `idleTimeoutMinutes` | number | `30` | 空闲自动收起 |
| `stopWhenDisconnected` | boolean | `true` | 断线自动收起 |
| `captureTitle` | string | `edge页面抓取` | 抓取会话工作区名 |
| `captureDir` | string | 自动 | 抓取产物目录 |
| `kbRoot` | string | `E:/DSH工作区/论文/知识库` | 知识库根目录 |
| `kbCollection` | string | `页面抓取` | 知识库 collection |
| `kbPython` | string | DSH 内置 | 跑 `kb.py` 的解释器 |

## `port`

监听端口，只绑 `127.0.0.1`。

- 默认 17333。
- 被占用时在 **17344 以内**顺序查找下一个可用端口（12 个候选）。
- 扩展并行探测这些端口上的 `GET /edge-bridge/ping`，所以**改端口不需要改扩展**。

校验：非整数或超出 `1..65535` 时回落到默认值并打一条 warn。

什么时候需要改：你有别的服务占着 17333 到 17344 这一整段（很少见），或者要做端口白名单。

```yaml
port: 17400
```

> 扩展的探测区间写死在 `background.js` 的 `DISCOVERY_FIRST_PORT` / `DISCOVERY_PORTS` 里（17333 起 12 个）。改到区间外需要同时改扩展并重新加载。

## `token`

配对令牌。扩展必须出示它才能完成握手。

- 未配置时首次启动自动生成 32 字符的 URL-safe 随机串，写入 `E:\.dsh\edge-bridge-token`（权限 `0600`）。
- 已存在令牌文件时读文件，不重新生成——所以重启 DSH 不会导致扩展掉线。
- 显式配置 `token` 时优先用配置值，令牌文件仍会写入（方便在 `edge_status` 里展示）。
- 更换令牌后扩展必须重新粘一次。

```yaml
token: "RgUMLbk8DB-gSXIGirDcnLKTNG9Q3pRs"
```

安全建议：不要把它提交进版本库；`.gitignore` 已经排除 `edge-bridge-token` 与 `*.local.json`。

## `autoStart`

| 值 | 行为 |
| --- | --- |
| `false`（默认） | 会话开始时只有 `edge_bridge` 一个控制工具；模型需要时自己 `start` |
| `true` | 插件加载时立即注册七个浏览器工具 |

**默认 false 是这个插件的核心取舍**：七个工具的参数描述加起来约两千 token，绝大多数会话用不到浏览器。`autoStart: true` 适合"专职浏览任务"的 profile，或 TUI 里不方便多轮调用 `start` 的场景。

## `idleTimeoutMinutes`

空闲多少分钟后自动 `stop`（卸载工具，保留连接）。

- 默认 `30`。
- `0` 表示不超时——工具一直挂着，直到显式 `stop` 或 DSH 退出。
- 每 30 秒扫一次；"空闲"指没有任何 `edge_*` 调用（插件包装了 `bridge.request`，每次调用都会 `touch()`）。

注意：`start` 之后即使一次都没用，也从 `start` 那一刻开始计时。

## `stopWhenDisconnected`

扩展断线后是否自动收起工具。

- 默认 `true`，宽限 **60 秒**：短暂重连（比如 Edge 重启 service worker）不会冲掉工具。
- `false` 时工具保持注册；此时调用会报 `the Edge extension is not connected`。

## `captureTitle`

抓取会话总结写到哪个工作区。默认 `edge页面抓取`。

插件启动时会 `ensure()` 这个工作区（不存在就创建），并在 4 秒后再试一次——因为 `workingDirectory` 服务可能晚于插件加载就绪。

```yaml
captureTitle: 业务页面抓取
```

## `captureDir`

抓取产物（会话总结、index.json）的目录。默认在 `captureTitle` 对应的工作区里。

手动指定时用绝对路径；相对路径相对工作区解析。

## `kbRoot`

知识库根目录，默认 `E:/DSH工作区/论文/知识库`。

插件在这里写三处：

```
<kbRoot>/补充/原文/<kbCollection>/<日期>_<时刻>-<slug>.html
<kbRoot>/补充/条目.json
<kbRoot>/<kbCollection>/清单.md
```

不需要抓取功能时可以忽略它；但如果 `kbRoot` 不存在，抓取按钮会失败并在会话总结里记下原因。

## `kbCollection`

写进知识库的 collection 名，默认 `页面抓取`。

它同时决定：

- 快照子目录名（`补充/原文/页面抓取/`）
- 清单文件位置（`页面抓取/清单.md`）
- 条目里 `collections` 数组的一项
- 检索时的 `--collection` 参数

在同一个知识库里区分用途时改这个：

```yaml
kbCollection: 法规原文
```

## `kbPython`

执行 `kb.py` 的解释器。默认用 DSH 自带运行时：

```
E:/.dsh/dsh-runtimes/dsh-next-primary-runtime/dependencies/python/python.exe
```

调用方式是 `spawn(kbPython, ['-X', 'utf8', 'kb.py', ...])`，`cwd` 为 `kbRoot`，环境变量加 `PYTHONIOENCODING=utf-8`，避免中文路径与控制台编码问题。

若 `kb.py` 不在 `kbRoot` 下，抓取会失败并给出 stderr 前几行——不会静默丢数据。

## 完整示例

```yaml
# cordis.patch.yml
- insert:
    - id: edge-bridge
      name: dsh-edge-bridge
      config:
        port: 17333
        autoStart: false
        idleTimeoutMinutes: 30
        stopWhenDisconnected: true
        captureTitle: edge页面抓取
        kbCollection: 页面抓取
        kbRoot: E:/DSH工作区/论文/知识库
```

## 兼容性

| 插件版本 | 扩展版本 | 说明 |
| --- | --- | --- |
| 0.3.x | 0.3.x | 完整支持 `ref` / `expect` / `effect_state` / 能力位 |
| 0.3.x | 0.2.x | 连接可用；`edge_act` 没有 `effect_state` 行；`edge_inspect` 不返回 `ref` |
| 0.2.x | 0.3.x | 可用；扩展多声明能力，插件不读 |

版本不一致时 `edge_status` 的 `caps:` 行会直接点出来，`edge_bridge` 的日志里也有一条 warn。**改完扩展记得在 `edge://extensions` 点重新加载**——只重启 DSH 不会替换 service worker 的代码。
